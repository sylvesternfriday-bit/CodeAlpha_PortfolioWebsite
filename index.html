How I use each technology

Every technology on the shelf has a job in my workflow. Here is what each one is, why it matters, and how I use it to build websites that look good, load quickly and work on every screen.

HTML5

HTML5 is the foundation of every web page. It describes the meaning of content: headings, paragraphs, navigation, forms, images, buttons and sections. I use semantic elements such as header, nav, main, section and footer so that pages are well organised, easier for search engines to understand, and accessible to people who use screen readers or keyboards. Good HTML also means properly labelled form fields, meaningful alt text on images and a clear heading structure, because a strong structure makes the styling and scripting that follow much simpler.

CSS3

CSS3 controls how a page looks and how it adapts. I use Flexbox and CSS Grid to build flexible layouts, media queries to make designs respond to phones, tablets and desktops, and custom properties to manage colours and themes in one place. Transitions, transforms and keyframe animations add polish, such as hover effects, fading sections and the 3D books on this page. I care about spacing, typography and contrast so that a design feels balanced and stays readable, whether it is shown in a dark theme or a light one.

JavaScript

JavaScript brings a page to life. It handles clicks, forms, menus, sliders, filtering, timers and everything else that reacts to the visitor. I use modern ES6+ features such as arrow functions, template literals, modules, promises and async/await, and I work with the DOM and browser events to build interactive features. Projects like my music player and photo gallery come from this: playback controls, playlists and category filtering are all JavaScript logic that I write to stay organised and easy to maintain.

React.js

React.js is a JavaScript library for building user interfaces out of small, reusable components. Instead of manually updating the page, I describe what the interface should look like for a given state, and React updates it efficiently when the data changes. I use components, props, state and hooks such as useState and useEffect to build dynamic interfaces like forms, lists and dashboards, keeping every piece of the interface focused, reusable and easy to test.

Next.js

Next.js is a framework built on top of React that adds what a real website needs: file-based routing, shared layouts, server-side rendering, static generation and image optimisation. These features help pages load quickly and improve search engine visibility, which matters for businesses that want to be found online. I reach for Next.js when a project grows beyond a single page and needs a clear structure, multiple routes and strong performance.

Tailwind CSS

Tailwind CSS is a utility-first framework. Rather than writing a separate stylesheet for every component, I compose designs directly in the markup using small classes for spacing, colour, typography, flexbox, grid and responsive breakpoints. This keeps styling consistent, speeds up building and makes responsive design easier, because a layout can change at every screen size with simple prefixes. It pairs especially well with React and Next.js.

Other Frontend Tech

Beyond the main stack, I keep exploring the wider frontend ecosystem: mobile-first and responsive design principles, accessibility, performance optimisation, browser developer tools and GitHub for hosting and sharing my projects. Technology keeps evolving, so I treat learning as part of the job and bring in new tools only when they help me build something cleaner, faster or easier to use.

Together these tools let me take a project from idea to a polished, responsive website: structure with HTML, design with CSS, behaviour with JavaScript, and scale and speed with React, Next.js and Tailwind CSS. If you have a project that needs any of this, let's talk.
